# RESUMEN DEL SISTEMA - DERECHOS ART

ESTE DOCUMENTO SIRVE COMO MEMORIA TECNICA Y GUIA DE REFERENCIA PARA EL MANTENIMIENTO Y DESARROLLO DEL PROYECTO DERECHOSART.COM.AR.

## 1. ARQUITECTURA GENERAL
EL SISTEMA ESTA DIVIDIDO EN DOS PARTES PRINCIPALES:
1.  **SITIO WEB PRINCIPAL Y SISTEMA DE GESTION:** BASADO EN UN PATRON MVC PERSONALIZADO CON UN FRONT CONTROLLER (`public_html/index.php`).
2.  **SUBSISTEMA QUIMEY:** UN SISTEMA INDEPENDIENTE UBICADO EN `public_html/quimey/`, CON SU PROPIA BASE DE DATOS Y ESTRUCTURA MVC.

---

## 2. SITIO WEB PRINCIPAL (MVC)

### RUTEO Y CONTROL DE ACCESO
- **FRONT CONTROLLER:** `public_html/index.php` CENTRALIZA TODAS LAS PETICIONES.
- **URLS AMIGABLES:** GESTIONADAS POR `public_html/.htaccess`, REDIRIGIENDO TODO A `index.php`.
- **SEGURIDAD:** INCLUYE PROTECCION CONTRA CSRF, REGENERACION DE ID DE SESION EN LOGIN Y CONTROL DE ACCESO (IDOR) EN LOS MODELOS SEGUN EL ROL DEL USUARIO.

### CAPA DE DATOS (MODELOS)
- **Database.php:** IMPLEMENTA EL PATRON SINGLETON PARA LA CONEXION PDO.
- **AuthModel.php:** MANEJA USUARIOS Y CREDENCIALES (TABLA `usuarios`).
- **FormModel.php:** GESTIONA DATOS PARA FORMULARIOS (PROVINCIAS, LOCALIDADES, CATEGORIAS, ART).
- **GestionModel.php:** EL MODELO MAS COMPLEJO. MANEJA LA PERSISTENCIA DE CONSULTAS EN MULTIPLES TABLAS (`consultas`, `consultas_accidentes_trabajo`, `consultas_despidos`, `consultas_enfermedades_profesionales`).

### CAPA LOGICA (CONTROLADORES)
- **PaginasControlador.php:** MANEJA LAS VISTAS PUBLICAS Y EL PASAJE DE METADATOS SEO.
- **AuthController.php:** GESTIONA EL LOGIN, LOGOUT Y ALTA DE USUARIOS.
- **GestionController.php:** CONTROLA EL PANEL DE ADMINISTRACION (`/gestion`).
- **ApiController.php:** MANEJA LOS ENDPOINTS AJAX PARA ACTUALIZACIONES EN TIEMPO REAL, ELIMINACION, RESTAURACION Y LA RECEPCION DEL FORMULARIO DE CONTACTO.
- **UbicacionController.php:** GESTIONA LA CARGA DINAMICA DE LOCALIDADES POR PROVINCIA.

### CAPA DE PRESENTACION (VISTAS)
- **Layout:** `vistas/encabezado.php` Y `vistas/pie_pagina.php`.
- **Estructura SEO:** CONFIGURADA EN `config/SEO_CONFIG.php`. LOS METADATOS SON DINAMICOS Y SE PASAN DESDE EL CONTROLADOR.
- **Performance:** USA CRITICAL CSS INLINE Y CARGA DIFERIDA DE ESTILOS Y SCRIPTS. ICONOS SVG INLINE SINCRONIZADOS CON FONT AWESOME 6.5.1 PARA PARIDAD TOTAL CON PRODUCCION.

---

## 3. FORMULARIO DE CONTACTO Y API
1.  EL FRONTEND ENVIA UN POST A `/api/consultas/nueva`.
2.  `ApiController::procesarNuevaConsulta` RECIBE LOS DATOS Y LLAMA A `GestionModel::guardarNuevaConsulta`.
3.  EL MODELO:
    - VALIDA DATOS OBLIGATORIOS POR CATEGORIA.
    - DETECTA DUPLICADOS POR NOMBRE/APELLIDO.
    - GUARDA EN LA TABLA MAESTRA `consultas` Y EN LA TABLA DE DETALLE CORRESPONDIENTE.
    - DISPARA UN EMAIL DE AVISO VIA `MailService`.
    - REGISTRA EL EVENTO EN GA4 (GOOGLE ANALYTICS 4).

---

## 4. SISTEMA DE GESTION (BACKOFFICE)
- **ACCESO:** RESTRINGIDO POR LOGIN.
- **ROLES:**
    - **ADMIN (ROL 1):** VE TODAS LAS CONSULTAS Y GESTIONA USUARIOS.
    - **USUARIO (ROL 2):** SOLO VE LAS CONSULTAS QUE LE HAN SIDO ASIGNADAS.
- **FUNCIONALIDAD:** PERMITE EDITAR, ELIMINAR (LOGICO), RESTAURAR Y MARCAR COMO LEIDAS LAS CONSULTAS. TAMBIEN PERMITE ASIGNAR CONSULTAS A DIFERENTES OPERADORES.

---

## 5. SUBSISTEMA QUIMEY
- **UBICACION:** `public_html/quimey/`.
- **DATABASE:** USA UNA BASE DE DATOS INDEPENDIENTE (`u538722186_cami` EN PRODUCCION).
- **CONEXION:** GESTIONADA POR `quimey/config/Conexion.php`.
- **PROPOSITO:** GESTION DE FICHAS DE "JOVENES" (PACIENTES).
- **ESTRUCTURA:** MVC SIMPLE (`JovenController.php`, `Joven.php`, `views/jovenes/`).
- **INDEPENDENCIA:** NO COMPARTE LOGICA NI SESION CON EL SITIO PRINCIPAL.

---

## 6. CONFIGURACION DE ENTORNOS
EL SISTEMA DETECTA AUTOMATICAMENTE SI ESTA EN `localhost` O EN PRODUCCION (HOSTINGER) PARA CARGAR LAS CREDENCIALES CORRECTAS EN:
- `config/db_credentials.php` (SITIO PRINCIPAL)
- `quimey/config/Conexion.php` (QUIMEY)

---

## 7. SEO, ANALYTICS Y CONVERSIONES
- **SEO_CONFIG.php:** CENTRALIZA TITULOS Y DESCRIPCIONES POR PAGINA.
- **Schema.org:** GENERA JSON-LD AUTOMATICAMENTE PARA `Organization`, `Breadcrumb` Y `FAQ`.
- **GA4 Y GOOGLE ADS:** CONFIGURADOS EN `vistas/encabezado.php`. SE UTILIZA UNA SOLA ETIQUETA GLOBAL (gtag.js) PARA AMBOS SERVICIOS.
- **TRACKING DE CONVERSIONES (GOOGLE ADS):**
    - **WhatsApp:** SE DISPARA AUTOMATICAMENTE DESDE `publico/js/ga4_events.js` AL DETECTAR CLICKS EN ENLACES `wa.me`.
    - **Formulario:** SE DISPARA DESDE `vistas/paginas/contacto.php` UNICAMENTE CUANDO SE MUESTRA EL MENSAJE DE EXITO TRAS EL ENVIO.

---

## 8. NORMAS Y PREFERENCIAS DE DESARROLLO
- **NOMENCLATURA:** TODOS LOS NOMBRES DE VARIABLES, FUNCIONES, CLASES Y ARCHIVOS DEBEN ESTAR EN CASTELLANO, SIGUIENDO EL ESTILO PascalCase Y SIN USAR ACENTOS.
- **ESTILOS (CSS):** LOS ESTILOS DEBEN IR SIEMPRE EN ARCHIVOS ESPECIFICOS DENTRO DE `publico/css/`. NUNCA USAR CSS INLINE.
- **SEO:** TODA MODIFICACION ESTRUCTURAL DEBE PRIORIZAR LA OPTIMIZACION SEO (SEMANTICA HTML, CARGA DIFERIDA, METADATOS).
- **ENTORNO:** EL CODIGO ESTA DISENADO PARA CORRER EN HOSTINGER BAJO LA CAPA DE CLOUDFLARE. TENER EN CUENTA POSIBLES CACHEOS Y CONFIGURACIONES DE REESCRITURA.
